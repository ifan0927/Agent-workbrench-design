# B．配置實際生效：優先驗證

狀態：已獲授權實作，B1–B4 最小案例完成驗證。驗證日期：2026-09-10。

實作與重跑：[lab/B](../../lab/B/README.md)；證據、限制與結論集中在 [B 組結果](../../lab/B/RESULTS.md)。下表保留原始驗證問題與通過條件。

[實驗入口與執行前提](README.md) · [相關候選設計](../design/configuration.md)

這組直接對應工作台的核心價值：集中維護、按次組裝，但不全部載入。

| ID | 驗證問題 | 最小做法 | 通過條件／設計影響 |
| --- | --- | --- | --- |
| B1 | 指引分層與衝突是否符合預期？ | 準備短小的共用約定、repo AGENTS.md、模式與任務輸入，包含一個刻意衝突的例子。 | 能說明有效來源與順序；必要限制有產物或執行證據，不能只依 agent 自述。 |
| B2 | 選用 skills 是否對應實際集合？ | 放入選用、未選用、同名及缺少依賴的測試 skills。 | 對照 Codex 發現結果、警告與實際行為，知道哪些來源額外帶入能力。 |
| B3 | 共用配置更新是否影響執行中工作？ | A 使用配置 v1 執行時更新共用來源，讓 B 使用 v2。 | A 的有效配置保持 v1，B 使用 v2；原生檔案監看不意外破壞快照。 |
| B4 | 模型與工具設定是否確實採用？ | 檢查有效模型、推理設定及必要工具；以不存在的配置測試錯誤路徑。 | 支援的設定可確認，缺失清楚回報；不把已請求設定當成已生效。 |

Skills 有多個發現來源，同名項目不會合併，初始清單也可能因預算而省略。平台選用集合、原生可發現集合、實際讀取與正確遵循須分別判斷。[Codex Skills](https://developers.openai.com/codex/skills/)
