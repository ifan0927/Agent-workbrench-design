## 實驗前的文件與接口查核

以下問題先查文件與實作依據，不用模型成功回應代替判斷。

| 問題 | 需要取得的結論 |
| --- | --- |
| 訂閱使用情境 | 個人帳號、目標 repo 可見性與自建工作台使用方式是否有適用依據；技術成功不等於使用條件已確認。 |
| 登入與刷新來源 | 平台採用哪個登入／刷新實作、誰維護；外部 token 接口不替平台實作整套 OAuth。 |
| 接入版本 | 固定 Codex 版本是否具備外部認證、刷新回呼、結構化結果、取消及 skills 發現接口。 |
| 範圍與用量 | 指定測試 repo、認證安排、模型／模式、turn 數與執行時間上限；模型只記實際 token，不估算金額。發布能力另列授權。 |

2026-09-10 查閱的官方文件將 `chatgptAuthTokens` 標為 experimental，要求 host application 管理認證生命週期；刷新回呼等待約十秒。執行前仍需核對固定版本與現行文件。[Codex app-server](https://developers.openai.com/codex/app-server/)

## 結果紀錄與設計決定

每個切片只保存必要內容：版本與有效配置、預期、實際證據、通過／失敗／未驗證、對架構的影響，以及模型 token 用量。依使用者 2026-09-10 的確認，後續實驗不換算模型金額、不要求人工耗時計量或成本收益作通過條件；保留必要問題與接手原因即可。既有歷史結果不回寫成新規則。

模型用量共通紀錄方式：

- 保存工作／attempt／thread／turn 身分、完成／失敗／取消狀態，以及 input、cached input、output、total tokens；來源提供額外細項時保留其名稱及包含關係。
- Cached input 已包含在 input，不重複相加。Thread 累計值依前後觀測去重；缺前值時保存已知 thread 合計，不虛構逐 turn 差額。Resume 沿用同 thread 時仍遵守此規則。
- 失敗／取消／連線不明若只取得部分用量，標示 partial／unknown 與已知值；沒有回報不填零。沿用既有候選或回合時區分本次新增與交接鏈總量，不重複計費式加總。
- Turn 數與程序期限是實驗執行界限，不等於 token 硬上限，也不限制 Codex 每個 turn 內的模型請求數。

原始證據不得包含秘密；不建立大型成本儀表板。E 組需要的執行時間線、去秘密與完整性界線見 [E6](../../lab/E/README.md#6-執行軌跡與證據完整性)，不將過程可追蹤誤解為保存所有原始 RPC 或完整內部推理。

| 結果 | 後續設計方向 |
| --- | --- |
| 訂閱＋集中認證成立，維護成本可接受 | 繼續收斂 app-server 與平台認證模組。 |
| 技術成立，但接口或維護負擔過大 | 比較採用既有整合與 API 路線；不自動切換。 |
| 使用條件或可靠性不符合需求 | 重新選擇認證／接入方式，再決定是否接受成本或縮減範圍。 |
| 配置或成果交接不成立 | 先修正組裝、發現或保存邊界，不用增加永久 agent 角色補洞。 |
| LangGraph 仍需搭配另一套完整 controller | 縮減重複責任，或重新評估流程底層。 |
