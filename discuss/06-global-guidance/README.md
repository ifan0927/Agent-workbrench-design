# 06 跨專案共用指引

- 更新日期：2026-09-11（Asia/Taipei）
- 訪談進度：ready-for-synthesis
- 本場聚焦：哪些跨專案的 agent 好習慣值得集中維護，哪些應依工作、專案或任務調整
- 摘要確認：U01–U05 為使用者明確表達；研究整理、AI 推導與完整案例摘要未另經確認

## 1. 範圍與既有基準

本題只辨認跨專案想統一改善的 agent 行為，以及必須容許工作、專案或任務差異的習慣。本場不決定配置格式、角色矩陣、skills、LangGraph nodes 或初始化實作；專案資訊維護、角色與 context 配置、外層流程政策分別交 07／08／09。

沿用 [configuration](../../docs/design/configuration.md) 的既有基準：共用工作約定應保持短小；專案資訊由索引提供用途與線索，再由 agent 按工作需要逐層探索。重要方案取捨須取得使用者選擇；已授權範圍內的純實作細節由 agent 自主處理。所有 code 相關工作須由另一個 agent review。

[05-interaction-recovery](../05-interaction-recovery/README.md) U14 提出的「平台依當次 agent 性質初始化適用設定，工作流較偏向負責流程推進」仍是候選；不預設每種工作流整份替換全局 AGENTS.md，也不預設工作流只影響 graph。

## 5. 本場收斂與下次接續

- 本場已足以帶去統整的內容：U01 的研究校準要求、U02 的主動探索與不憑空假設、U03 的依工作指引驗證，以及 U04–U05 的缺漏時模型自主判斷最低必要驗證並回報方式。
- Ready 判斷：ready-for-synthesis，僅針對已談的探索與驗證切片。跨專案行為要求、工作差異及指引缺漏的處理已有足夠材料；這是訪談者對材料充分性的判斷，不代表完整摘要、外部研究或配置方案已批准。本輪未開始 synthesis。
- 本場未完成或刻意略過：未窮舉其他共用習慣；模型已獲自主判斷的驗證細節不再訪談。研究整理 O01–O02、分層解讀 O05 與完整案例摘要仍保留原身分；外部資料為初步官方實務對照，不宣稱已完成全面的最新研究或實證最佳性比較。
- 跨題及技術未決：專案索引維護交 07；工作／角色指引與 context 配置交 08；流程確保方式交 09。報告格式、配置格式及初始化實作不在本場決定，05 U14 仍為候選。
- 06 是否需要另一個明確 slice：目前沒有足以要求再開一場的具體未決行為；不為填滿規則清單續問。後續若發現反覆發生的新問題，再以該行為開明確 slice。
- 下次第一個值得問的問題：本 slice 不需續問。較有價值的接續是 07 中「專案指引應提供哪些驗證入口，讓 agent 找得到適用的驗證方式？」；須先讀 07 最新紀錄，已有答案則跳過，不把本句視為已啟動訪談或維護授權。
- 建議下一步：可由使用者授權對 06 已明確條目做 synthesis；亦可先續 07。保存不等於批准，不自行啟動統整或下一題。
