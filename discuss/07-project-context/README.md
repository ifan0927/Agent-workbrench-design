- 摘要確認：本輪啟動指令的範圍與界線已明確；尚未取得第一題回答，無新增訪談結論。

## 1. 範圍與既有基準

本場只辨認：在既有索引與按需探索基準下，哪些專案資訊仍容易讓 agent 找錯、漏讀或判錯適用性，值得由專案入口協助辨認。

沿用已確認基準，不重新訪談：

- [configuration：索引與閱讀自主性](../../docs/design/configuration.md#索引與閱讀自主性)：索引提供用途、方向與入口，agent 依工作需要逐層判斷閱讀內容與深度，也可探索索引外資訊；主動探索、不憑空假設，不全量載入文件。
- [configuration：專案 onboarding 與維護](../../docs/design/configuration.md#專案-onboarding-與維護)：原始 repo 文件仍是權威來源，索引不複製全文或取代原始文件，也不能把候選或歷史提案升格為現行規則。Bench agent 探索後提出改善建議，使用者確認後才修改；maintenance 由使用者手動觸發。
- [product：專案入場與 onboarding](../../docs/product.md#專案入場與-onboarding)：onboarding 是 project-level gate，核心為「看得到該看的、改得到該改的、驗得到該驗的」；local verification 與 authoritative CI／external verification 可分工。
- [workflow：依工作指引驗證與回報](../../docs/design/workflow.md#依工作指引驗證與回報)：依適用工作指引完成對應驗證；未規定時自行判斷並完成最低必要驗證，回報實際使用方式。不重問完整驗證清單或固定門檻。

本場不決定配置格式、metadata schema、完整索引欄位、skills、角色矩陣或 LangGraph nodes；工作／角色配置初始化仍是候選，交 08，外層流程政策交 09。能找到驗證入口不表示所有任務必須預先列出驗證方法；索引維護不構成當次工作的新 gate。不實際執行 onboarding／maintenance。
