## 1. 範圍與既有基準

本題包含：project 已 ready 時，單次模糊目標的初步探索、必要追問、自主假設、clarification 連續性與可交接成果。本場不談：重新 onboarding／maintenance、issue 或 task source of truth、完整開發交付流程、長時間 agent 協調角色、完整狀態機與 session 保存技術。

沿用基準：

- [docs/product.md](../../docs/product.md)「產品假設」與「專案入場與 onboarding」：project onboarding 是 project-level global gate；本場的單次目標清晰度不是重新入場條件。模型可自主探索，但不無限擴張。
- [docs/product.md](../../docs/product.md)「使用體驗與工作範圍」：使用者可下目標、補資訊與回答必要問題；討論／需求釐清、研究與開發不必依序全走。
- [docs/design/workflow.md](../../docs/design/workflow.md)「身分與 context」與「研究交付或等待回答」：普通留言不必立即啟動 agent；必要產品取捨應保存問題與目前成果後等待，不把提案當成採納。
- 本場明確沿用已統整的 01-project-onboarding 結論：project 已具備「看得到該看的、改得到該改的、驗得到該驗的」能力，缺少當次任務細節不觸發重新 onboarding。
