## 1. 範圍與既有基準

本場只談模式／角色的工作方向與可觀察行為，先辨認目標、成果、授權及專案指引是否已足夠，不預設新增角色規則。不要求角色矩陣、完整 AGENTS.md、prompt 全文、配置 schema 或 LangGraph nodes。Skills 選用與 context 交接可另切 slice；外層 review／修正政策交 09。本次只授權更新本檔，不授權配置初始化、安裝、實驗、服務開通、部署或發布。

- [product「使用體驗與工作範圍」](../../docs/product.md#使用體驗與工作範圍)：討論／需求釐清、設計／技術研究、開發／修正三種入口，不必依序全走。
- [workflow「目標釐清與必要取捨」](../../docs/design/workflow.md#目標釐清與必要取捨)：需求探索可接續設計，進入開發須使用者確認；重要取捨與純實作細節的自主界線沿用。
- [workflow「Issue 任務單與程式完成」](../../docs/design/workflow.md#issue-任務單與程式完成)：以固定格式 issue 交接，開發成果為完成其程式要求；PR 通過、合併及採納分開。
- [workflow「Code 工作的獨立 review」](../../docs/design/workflow.md#code-工作的獨立-review)：所有 code 工作須由另一個 agent review；具體角色配置與隔離未定。
- [configuration「內容分工」「索引與閱讀自主性」](../../docs/design/configuration.md)：共用指引與專案索引提供方向，agent 按需探索，不憑空假設；控制額度並避免無關探索，不新增固定探索步數或必讀清單。依適用工作指引完成驗證，未規定時自行判斷最低必要驗證並完成，回報實際方式。
- [configuration「當次 agent 角色與配置初始化候選」](../../docs/design/configuration.md#當次-agent-角色與配置初始化候選)：平台依當下 agent 性質初始化適用設定、工作流偏向影響外層流程，仍是候選，不是已確認架構。
- 已核對 [02 O06 與整合追蹤](../02-clarification/README.md)：模式是否完全只有階段差異仍待核對。
- 已核對 [05 U14、J03、O13–O14 與整合追蹤](../05-interaction-recovery/README.md)：使用者候選與 AI 分工解讀保持原身分；未採納完整全局規則重建，也未確認模式只影響流程。
