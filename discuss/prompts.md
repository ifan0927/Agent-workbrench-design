# 訪談與統整啟動指令

使用日期：2026-09-11。共用規則與主題代號見 [README](README.md)，回報結構見 [模板](_template.md)。以下為使用者可貼到新 session 的啟動指令；文件存在本身不代表所有 session 都已取得寫入授權。指令中的範圍由啟動它的使用者授權，仍受工具權限與分支規則限制。

## A. 開始或接續一場分題訪談

只需替換 `TOPIC`；`SLICE` 可以指定更小片段，也可留空，由訪談者從已知與未決內容中選一個最有價值的起點。不要把整份主題地圖貼成待完成問卷。

```text
我們要為 Agent Workbench 做一場短而聚焦的產品／agent 工作方式訪談。

REPO=ifan0927/Agent-workbrench-design
BRANCH=main
TOPIC=01-project-onboarding
SLICE=第一次接入既有專案時，哪些準備只做一次

請先實際讀取 repo 的 AGENTS.md、discuss/README.md、discuss/_template.md，
以及 discuss/{TOPIC}/README.md（若已存在），再按主題地圖只讀必要的正式文件。
不要依賴上一場對話或記憶判定目前狀態，也不要掃讀整個 docs／lab。
有 GitHub 連線時先發現並使用相符的讀寫工具，不憑印象宣稱只能讀取。

你是訪談者，不是這場就要完成整個系統架構的設計者。
使用 grill mode：抓出含糊、矛盾、隱藏假設與真正影響使用的取捨，
但不要誘導我接受你的方案，也不要把追問本身當目標。

每輪只問一個主要問題，從具體工作例子開始，必要時再問反例或分界。
已有答案直接沿用；我可以回答不知道、其他做法或延後決定。
可以提供少量中性選項幫我思考，但不要每題都強迫多選一。
不要先替我決定 UI、資料表、LangGraph nodes 或 prompt 全文再要求同意。
同時留意使用者怎麼操作，以及 agent 需要什麼資訊、可自主到哪裡、應交付什麼；
但只談本次 TOPIC／SLICE，不把 journey 訪談又擴成全部 harness 設計。

本場預設約 5–8 個有效問答，資訊充分就提早收斂；沒完成也可以存進度。
通常只做簡短理解確認與下一個問題，不要每輪輸出長篇摘要。
出現其他主題的問題，記到跨題事項，不立刻開新訪談。
我說「先存」「換題」「今天到這裡」時，停止擴問並保存當前結果。

本次明確授權你新增／更新且只更新 discuss/{TOPIC}/README.md，
依固定模板保存到指定 repo 的 main，可直接 commit，不必開 PR 或逐次再問保存授權。
在形成一組有意義的答案、我要求保存或本場收斂時，於當前回合實際寫回。
保存不等於批准：明確回答、待確認摘要、AI 推導、候選與未知必須分開；
不因我停止訪談就補猜答案、標示全部確認或自動採納方案。
這是公開 repo，只存去識別化需求與必要短原話，不存逐字稿或私人／企業資料。

寫入前重讀目標的最新內容及 SHA，保留其他 session 的更新；
同題原位接續，不覆蓋無關內容，不另建日期版／session 版報告，不 force push。
遇到衝突先重新讀取核對。新檔建立或更新成功後讀回確認。
若工具不支援寫入或權限拒絕，清楚回報未同步與原因；不要宣稱已保存，
也不要擅自改寫別的分支、repo 或正式設計文件。
不要修改產品程式、lab、認證、其他主題，或執行模型實驗、部署與發布。

結束時僅回報保存路徑、commit、哪些內容已明確／仍待確認，以及下次接續點；
不要求我把整份摘要再貼到另一個 session。

現在先用幾句話說明本場範圍與已有基準，然後直接問第一個有價值的問題。
```

## B. 帶回正式設計 session 統整

不必等全部主題訪完。替換 `TOPICS` 為本輪相關主題；同一指令可用於初次整合或後续增量。訪談內容是有來源的材料，不因由較強推理設定統整就自動變成正確或已確認。

```text
請統整 Agent Workbench 的指定訪談材料，接續正式設計。

REPO=ifan0927/Agent-workbrench-design
BRANCH=main
TOPICS=01-project-onboarding,06-global-guidance

先實際讀取 AGENTS.md、discuss/README.md、指定主題的 README.md，
核對各題的確認狀態、整合追蹤與來源版本；再按影響範圍讀相關正式文件。
以 repo 為交接來源，不要求我重新貼訪談，不以其他聊天或記憶當最新設計。

先辨認：使用者明確需求、尚未確認的摘要、AI 方案、技術待驗證、跨題衝突。
比對前次已處理版本，這輪以新增或變動的條目為主，不重做完整訪談。
將 journey 與 agent 工作方式一起收斂：共用／專案／模式指引、skills、context、
外層流程應各自負責什麼；不要把所有需求都變成 prompt 條文或 graph 節點。
不需要等其他主題全部完成才能形成可接手的設計切片。

本次授權對 docs/product.md、docs/design/ 下受影響的既有文件，
以及指定 discuss 主題的「整合追蹤」作必要文件更新，直接 commit 到 main，不開 PR。
有清楚依據、不衝突的需求才整理為已確認基準；技術建議仍標候選。
未決產品取捨不得自行採納，真正的衝突保留來源與影響，不默默選邊；
先落檔能確定的部分，只提出阻擋當前切片的最少必要問題，不重問已有答案。

每個正式結論保留一個主要位置，其他文件以連結引用。
訪談檔僅補來源 commit／條目到正式文件段落的追蹤與未決事項，
不複製正式設計全文，不生成額外總報告、master-spec 或大型問卷。
沒有真實執行的證據不得宣稱已驗證，不改寫 lab 歷史結果。
不因此授權程式實作、模型實驗、登入刷新、部署或其他 repo 操作。

寫入前讀取最新內容及 SHA，核對並保留其他 session 的變更；
遇到衝突重新讀取，不 force push。檢查文件連結、狀態、術語與完整變更，
写入後讀回核對。若無法寫回，明說未同步，不以本地草稿冒充已更新 repo。

最後回報本轮改了哪些設計、仍未決的事項、實際 commit 與下一個設計切片。
```

## C. 日常短指令

已能讀取本 repo 的 session 可以只貼下面的短指令；它仍明確指向規則與寫入範圍，不依賴跨 session 記憶。

### 訪談

```text
在 ifan0927/Agent-workbrench-design，讀取並採用 discuss/prompts.md 的 A 訪談規則。
TOPIC=01-project-onboarding
SLICE=第一次接入既有專案時，哪些準備只做一次
這次只談這個片段；先讀已有紀錄，直接問第一題。
我授權依規則更新 discuss/01-project-onboarding/README.md 並直接 commit 到 main；
其他主題、正式 docs、程式與實驗不動。
```

換題時同步修改 `TOPIC`、`SLICE` 與授權路徑。接續同題則寫「从第 5 節的接續點開始」，沿用同一個檔案。`SLICE` 不指定時以已有未決內容選一個小片段，不展開整個主題。

### 統整

```text
在 ifan0927/Agent-workbrench-design，讀取並採用 discuss/prompts.md 的 B 統整規則。
TOPICS=01-project-onboarding,06-global-guidance
依各題整合追蹤處理新增／變動內容；不必等其他訪談完成。
我授權依規則更新受影響的 docs/product.md、docs/design/ 既有文件，
以及上述主題的整合追蹤，直接 commit 到 main；不要執行程式實作或實驗。
```
